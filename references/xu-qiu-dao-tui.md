# 需求倒推法（从需求向下推演，而非从风口向上猜）

## R — 原文 (Reading)

> 一切都是基于需求，一切都是基于需求去延伸的思考。你的需求是什么？很简单，你做生意的需求就是你要卖产品，卖服务…真正的做事情是什么？是你要基于需求，基于需求的逻辑向下去推演，去思考，要通过逻辑来验证，是不是，一个可执行，可以去实践的事情？

> 夏天晚水，冬天晚冰。不同的环境下面，不同的人有不同的需求。老人有老人的需求，孩子有孩子的需求，妇女有妇女的需求，打工组有打工组的需求，老板有老板的需求。

> 只有一个人，拥有持续挖掘需求的能力，他才能在这个市场上持续赚钱。

> 我可以先假装客户去了解你的工作链路吗？

— 鲁大魔，012 这段很详细了听懂，做到会不一样（2026-09-10，10分26秒）／033 零成本创业（2026-08-14，27分17秒）

---

## I — 方法论骨架 (Interpretation)

这是全书最实用的一条**推理路径**：从需求往下推，一直推到"加谁的联系方式"。

它的对立面是"从风口向上猜"——先看哪个赛道火、谁赚了钱，再倒过来想自己能不能进去。主播明确反对后者，因为风口结论是别人的，需求结构才是可验证的。

**推演的层次是：**

```
需求 → 场景/人群 → 需求频率 → 未满足形态 → 需要什么人 → 从哪找 → 具体动作
```

每一步都用"逻辑"验证是否可执行。以旅游淡季为例，主播当场演示了完整链条：

1. 需求：夏天玩水、冬天玩冰（季节属性决定需求形态）；
2. 场景/人群：老人、孩子、妇女、打工者、老板各有各的需求；
3. 推演：基于季节属性推出一个**替代淡季**的新旅游产品；
4. 人员：需要什么样的人？合伙人也行，或与已有这类产品的公司合作；
5. 渠道：从哪些渠道找？——线上旅游产品与渠道、抖音、小红书搜索"旅游"，加上对方联系方式建立合作；
6. 动作："我可以先假装客户去了解你的工作链路吗？"

**这条方法论的两个特点：**

- **强制性下落**：不允许停在"这个赛道不错"的层面，必须一路推到可执行动作，否则不算完成。
- **零成本起步**：前三层（需求、人群、频率）不需要花钱也不需要人脉，正好对应 `chuang-ye-liu-bu` 的第①②③步。

主播还给了一个重要的时间维度判据：优先选**长期需求**——"天要刮风，天要下雨，人要吃饭，这是雷打不动的东西"。在 026 的食品案例里，他正是用"食品是长周期需求"来解释为什么要从食品开始。

## A1 — 书中的应用 (Past Application)

### 案例 1：旅游淡季的替代产品（012）
- **问题**：旅游从业者淡季无客，反复问"这个行业怎么样"。
- **方法论的使用**：主播拒绝回答行业问题，改为从需求往下推——夏天玩水、冬天玩冰 → 老人/孩子/妇女/打工者/老板各有各的需求 → 基于季节属性推出淡季替代产品 → 反推需要什么人、去哪找人 → 线上搜索同类产品加联系方式建立合作 → 甚至可以先假装客户去了解对方工作链路。
- **结论**：替代方案写在需求结构里，不在创意里。
- **结果**：把"淡季没生意"的抱怨，转成一条可直接执行的合作开发清单。

### 案例 2：食品为什么适合两个什么都不懂的年轻人（026）
- **问题**：两个发小想创业，但没有任何行业专业知识。
- **方法论的使用**：主播恰恰认为"这个事情反而恰恰能做的点就在于这里"，理由是食品的售购面广、且属于长期需求。他们的目标不是赚钱，而是"把渠道拓展的这个方法，把渠道拓展的方法和工作的流程给它摸牌清楚"。
- **结论**：需求越长期、面越广，越适合作为练手的载体。
- **结果**：把创业目标从"赚钱"改成"摸清渠道方法"，指标也相应改变。

### 案例 3：从人的行为数据推产品（012）
- **问题**：如何找到能卖的产品。
- **方法论的使用**：从一个人的行为习惯推他未来的需求——"阿伟喜欢吹牛逼、喜欢好高骛远、喜欢在网上拍汽车、喜欢给美女点赞"，那么"等这个吊毛到 40 多（岁）…卖保健品给他"；喜欢打游戏 → 提供代练服务。
- **结论**：需求来自观察到的行为，不来自想象。
- **结果**：给出"观察群体/个体共识 → 推送相应产品"的可复制路径。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 想找一个能做的新方向/新项目，希望有客观依据而不是跟风。
2. 手上有一个产品或服务，但不知道还能卖给谁、还能做什么形态。
3. 生意有淡旺季或需求波动，需要找替代方案。
4. 面对一个"很火"的方向，想判断自己能不能切进去。
5. 想验证一个创意到底是真需求还是自己的一厢情愿。

### 语言信号 (用户的话里出现这些就应激活)

- "我该做什么产品/项目？" / "What product should I build?"
- "这个赛道能不能进？" / "Is this market worth entering?"
- "我的业务有淡季，怎么办？"
- "我的产品还能卖给谁？"
- "怎么验证这个需求是真的？"
- "现在什么最火？"（反向信号——不要跟着答，要拉回到需求层）

### 与相邻 skill 的区分

- 与 `chuang-ye-liu-bu`（创业六步）的区别：本能力是六步中**第②③步（定位产品 + 调研需求）所用的推理方法**；六步是覆盖全程的顺序框架。用户问"先做哪步"→ 六步；问"需求怎么找、产品怎么定"→ 本能力。
- 与 `kan-guang-gao`（看广告倒推）的区别：本能力从**内部需求结构下推**；看广告从**外部投放信号反推**。方向相反，可互为验证：广告证明需求真实存在，需求倒推给出你的切入口。
- 与 `zui-xiao-shi-yan-ti`（最小实验体）的区别：本能力产出**假设**；最小实验体**验证假设**。先用需求倒推提出假设，再用最小实验体去测。
- 与 `di-er-zeng-zhang-qu-xian`（第二增长曲线）的区别：第二增长曲线处理"已有业务如何长第二条线"；本能力处理"从零如何找到第一件事"。

## E — 可执行步骤 (Execution)

1. **锚定需求主体（谁的需求）**
   - 做法：不接受"市场有需求"这种表述。要求说出**具体人群**——年龄段、职业、收入层、所处场景。
   - 完成标准：能用一句话描述"谁、在什么场景下、产生什么需求"。

2. **拆出需求的场景与形态**
   - 做法：把同一人群的需求按场景/季节/生命周期拆开。例：老人/孩子/妇女/打工者/老板各有各的需求；夏天玩水、冬天玩冰。
   - 完成标准：产出 ≥3 个不同场景下的需求形态。

3. **判断需求频率与长期性（关键判据）**
   - 做法：问"这个需求多久发生一次？一年一次还是一周一次？"以及"十年后还存在吗？"
   - 完成标准：给出频率（数字）与长期性判断（长期需求 / 周期热点）。
   - 判停条件：**判定为短周期热点 → 回到步骤 1 换需求**。主播偏好的判据是"人要吃饭"这类雷打不动的需求。

4. **找出未满足的形态**
   - 做法：列出这个需求目前被满足的方式，再找其中**体验差、价格高、覆盖不全**的环节。
   - 完成标准：产出 ≥1 个具体缺口（不是"做得更好"，而是"缺少 X"）。

5. **反推人员与渠道**
   - 做法：把缺口翻译成"需要什么人"和"去哪找人"。主播的方法很直接：上网搜索同类产品 → 加对方联系方式 → 谈合作；甚至可以先假装客户去了解对方的工作链路。
   - 完成标准：产出 ≥3 个可联系的渠道或对象类型。

6. **收口为唯一动作，并转最小实验体验证**
   - 做法：把整条推演压缩成"我明天做的第一件事"，再交给 `zui-xiao-shi-yan-ti` 设计验证规模。
   - 完成标准：用户能说出具体的第一通电话/第一次搜索/第一次接触对象。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **用户已有明确业务、问的是运营/增长细节**：属于 `di-er-zeng-zhang-qu-xian` / `xing-jia-bi-yu-gong-ying-lian`。
- **技术驱动型创新（需求尚未被用户意识到）**：如早期智能手机、早期电动车——这类创新无法从既有需求倒推，本方法会得出"没有需求"的错误结论。
- **纯信息查询**：直接回答。
- **用户需要的是执行而不是再分析**：反复推演会变成新的拖延（见 ce20）。

### 作者在书中警告的失败模式

- **从风口/热点向上猜**：与 `kan-guang-gao` 的"持续投放"判据相反，追热点是无依据的猜测。
- **病急乱投医 / 拉熟人补自信**（ce05）：需求没验证就先去拉合伙人。
- **跳过第一步直接聊后面**（ce03）：需求调研（本能力）属于第③步，不能跳。
- **跨行业乱举例**（ce10）：不能把一个行业的需求结构直接搬到另一个行业。
- **空谈项目、追逐热点概念**（ce27）。

### 作者的盲点 / 时代局限

- **需求倒推创造不出新需求**：它擅长在既有需求里找更好的满足方式，不擅长开创品类。而主播自己投资的项目多在既有消费品赛道，这既是方法的一致，也是方法的局限。
- **"需求频率"的判据过于简化**：他只讲高频好，但高毛利低频（如婚庆、殡葬、教育）同样是成立的生意。
- **缺少样本与验证环节的约束**：主播说"通过逻辑来验证"，但逻辑验证 ≠ 市场验证。真正的验证必须靠 `zui-xiao-shi-yan-ti`，而他在口播中常常跳过这一步的描述。
- **"假装客户了解工作链路"的合规与伦理边界**：这是常规的竞品调研手段，但若涉及套取商业机密或在职竞业限制，存在风险，主播未作提示。
- **"长期需求＝好生意"是隐含假设**：长期需求可能已被巨头垄断（如食品、水电），对新进入者反而不友好。

### 容易混淆的邻近方法论

- **Jobs-to-be-done**：从用户要完成的任务出发，与本能力同向；本能力更强调"逐层下落直到可执行动作"。
- **设计思维（共情阶段）**：结构化地理解用户；本能力强调**推演链条不断链**。
- **蓝海战略**：找无人竞争的空间；本能力不排斥竞争激烈，而看需求频率与长期性。
