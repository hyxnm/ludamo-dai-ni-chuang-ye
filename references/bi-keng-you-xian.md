# 避坑优先法（先看前辈怎么死的）

## R — 原文 (Reading)

> 避坑优先法：先看前辈怎么死的，避开坑，剩下的就是利润。动作：强制拆解 3 个以上失败案例的致命点（如天天鉴宝流量错配）。
>
> 鲁大魔语录：先看别人怎么死的，你活下来的概率才大。

— 《鲁大魔·全能逆袭智库》logic/methodology.md「商业项目拆解 10 大心法」第 2 条／B 包 templates/pitfalls.md

> **来源说明**：出自技能包 B 的归纳文本，非 A 包原有 141 条口播切片转写。

---

## I — 方法论骨架 (Interpretation)

这是一条**研究顺序**上的规则：评估一个项目时，**先看失败案例，再看成功案例**。

它的推理是：成功案例的信息含量被幸存者偏差污染了——活下来的人会事后叙事，把运气讲成方法；而失败案例的致命点往往是结构性的、可复用的、且不撒谎。所以"看别人怎么死"比"看别人怎么赢"的信息密度更高。

具体化之后有三个要点：

1. **数量下限是 3 个。** 不是"了解一下风险"，是强制拆够 3 个以上失败案例。1 个是偶然，3 个开始出现共性。
2. **要拆到"致命点"，不是"失败原因"。** "他没坚持住""他运气不好"这类不是致命点；"流量属性与变现方式错配""现金流撑不到第二曲线盈利"这类结构性判断才是。
3. **坑是利润的反面。** 来源包的表述是"避开坑，剩下的就是利润"——这不是修辞，它对应 A 包 `zui-xiao-shi-yan-ti` 里"风险不能规避只能降低"的同一套世界观：你不靠押对赢，你靠不踩死人坑活下来。

**与 A 包既有能力的分工**：`zui-xiao-shi-yan-ti` 管"**把实验体缩到多小**"（规模维度），本卡管"**在开跑前先去看哪些坑**"（信息维度）。前者是风险控制，后者是风险识别，顺序是先识别再控制。

## A1 — 书中的应用 (Past Application)

### 案例 1：天天鉴宝的流量错配（methodology.md）
- **问题**：一个有大流量的账号为什么做不成生意。
- **方法论的使用**：把它的失败拆成**结构性致命点**——流量性质与变现方式错配（泛流量去做了需要精准流量的变现）。不是"没做好"，是结构不对。
- **结论**：流量大不等于能变现，匹配才是前提。
- **结果**：来源包把"流量与变现错位风险"固化成了 pitfalls 模板里的一个固定检查项。

### 案例 2：大兵（电竞椅）的现金流错判（A 包 `di-er-zeng-zhang-qu-xian` 同源案例）
- **问题**：学小米做生态，想靠第二曲线翻身。
- **方法论的使用**：拆出的致命点不是"第二曲线选错了"，而是**第一曲线现金流不足以烧到第二曲线盈利**，且竞争对手同样在烧钱。
- **结论**：失败点是结构性的（现金流相对量），不是执行性的。
- **结果**：给出"资金储备要以对手的资金量为参照，而不是自己的绝对数字"这一判断。
- **注**：此案例出自 A 包口播原文，本卡借用它说明"拆致命点"这一动作，可跨包互证。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 看中一个项目/加盟/赛道，已经很心动，需要在投钱前做一次冷静检查。
2. 只知道这个行业有人赚了钱，但说不出谁在这里亏过钱。
3. 朋友/招商方只讲成功案例，用户感觉不对但说不出哪里不对。
4. 已经踩过一次坑，想搞清楚是不是同一个坑会再踩。
5. 要写立项或可行性分析，需要风险章节而不是乐观预测。

### 语言信号 (用户的话里出现这些就应激活)

- "这个项目有什么坑？" / "what are the pitfalls of this business"
- "加盟/代理靠谱吗？"
- "别人做这个都赚了，我能做吗？"
- "有没有做这个失败的案例？"
- "帮我评估一下风险"

### 与相邻 skill 的区分

- 与 `zui-xiao-shi-yan-ti`（最小实验体）的区别：最小实验体管"**做多大**"；本卡管"**先看什么**"。顺序是本卡在前——先列出致命点，再决定实验体要缩到多小才能避开它们。
- 与 `liu-liang-pi-pei`（流量匹配）的区别：流量匹配是**一个具体的致命点类型**；本卡是找致命点的**通用动作**。
- 与 `chuang-ye-liu-bu`（创业六步）的区别：六步给顺序框架；本卡是第③步（需求调研）里的一个信息采集动作。
- 与 `kan-guang-gao`（看广告倒推）的区别：看广告找**谁在赚钱**（正向信号）；本卡找**谁死了、怎么死的**（负向信号）。两者应配对使用。

## E — 可执行步骤 (Execution)

1. **先锁定"同类"的边界**
   - 做法：定义什么叫同一个坑——同赛道 + 同规模量级 + 同城市层级。不同规模的失败没有参考价值（摆摊亏了不能推导出开店会亏）。
   - 完成标准：能用一句话界定"我要找的是什么样的失败案例"。

2. **找够 3 个失败案例**
   - 做法：从三类来源取——①本地同行的关店/转让（现场、二手设备转让、招租信息）；②公开信源（裁判文书、失信名单、投诉平台、行业群里的退出讨论）；③自己的间接人脉（供应商、房东、前员工）。
   - 完成标准：拿到 ≥3 个有具体时间、地点、规模的例子。
   - 判停条件：**若一个失败案例都找不到，这不是好消息**——要么信息渠道不够（继续找），要么这个赛道太新没有前例（按 `zui-xiao-shi-yan-ti` 把实验体压到最小再说）。

3. **拆致命点（不是失败原因）**
   - 做法：对每个案例追问到结构性层面——是流量与变现错配？现金流撑不住？供应链成本结构劣势？选址/人群判断错误？政策与合规？把答案写成一个**可检验的命题**。
   - 完成标准：每个案例产出 1 个结构性致命点，而不是"他没坚持/他运气差"。
   - 判停条件：若三个案例的致命点完全不同，说明样本太杂，回到第 1 步收窄边界。

4. **把致命点映射回自己的方案**
   - 做法：逐条问"我这个方案在这个点上会不会死"，标为**已避开 / 未验证 / 会踩**。
   - 完成标准：每个致命点都有明确标注。
   - 判停条件：出现 ≥1 个"会踩"且无法改动 → 输出"这件事现在不该做"并终止；出现"未验证" → 转为一条要验证的假设，交给 `zui-xiao-shi-yan-ti` 设计实验。

5. **写成红线并设检查时点**
   - 做法：把致命点转成 2–3 条红线（如"绝不先囤货""绝不自有资金占比超过 X"），并为每条设一个复查时点。
   - 完成标准：红线可数、可复查。

6. **汇报顺序：先说坑，后说利**
   - 做法：任何项目评估的输出都按"致命点 → 红线 → 机会"排序。
   - 完成标准：用户先看到的是坑。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **纯职业选择 / 求职判断**：用 `qiu-zhi-bi-keng-yu-mian-shi`。
- **已进入执行中段、问题是组织或交付**：本卡是立项前动作，中段的坑要靠复盘而不是预测。
- **赛道太新没有失败样本**（如全新品类）：强行找案例会制造假信号，应改用最小实验体。
- **用户要的是乐观测算**（收入预测、回本周期）：本卡只产出风险侧，不能替代财务测算。

### 作者（来源包）自身的盲点

- **幸存者偏差同样作用于失败案例**：失败者的公开叙述也有事后归因（"因为平台不行"），未必比成功者更诚实。
- **"3 个"是经验数，不是统计样本**：3 个案例无法支撑概率判断，只能生成假设。
- **失败案例的致命点未必适用于你的资源结构**：别人死于现金流，你可能有足够现金；别人死于选址，你可能做线上。映射时要核对前提，不能照搬。
- **可能导致过度避险**：只看坑会让人永远不动手。本卡必须配合 `zui-xiao-shi-yan-ti` 使用——识别坑之后是缩小实验体去验证，不是无限延后。

### 容易混淆的邻近方法论

- **事前验尸（Pre-mortem）**：假设项目已失败反推原因，靠想象；本卡要求**真实的、外部的**失败案例。
- **SWOT 的风险部分**：静态罗列；本卡要求拆到结构性致命点并映射回自己。
- **尽职调查（DD）**：面向投资与并购的合规财务核查；本卡是草根版、零成本、面向个人。
